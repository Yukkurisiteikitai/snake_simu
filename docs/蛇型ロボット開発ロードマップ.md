# 蛇型ロボット開発ロードマップ

Sep 29, 2026 · @Nikeri

## v1のゴールと前提

v1のゴールは「平らな室内の床で、床に置いたマーカーまで蛇行で這っていき、半径20cm以内で止まる蛇型ロボット」です。人を追いかけるのはv2に回します。

| 項目 | v1での決め方 |
| --- | --- |
| 環境 | 平らな室内の床（2Dとして扱う） |
| 移動方法 | 蛇行（lateral undulation）のみ |
| 目標 | 床に置いたArUcoマーカー |
| 自己位置 | 天井の外部カメラ＋頭に貼ったマーカー |
| 駆動 | シリアルバスサーボ 8〜12個、腹側に受動車輪 |
| 完成の判定 | 10回中8回以上、目標の半径20cm以内に着いて停止する |

制御の核は次の式です。γ（旋回バイアス）を目標方向との角度差に比例させるだけで、目標に向かって曲がります。

```latex
\varphi_i(t) = \alpha \sin(\omega t + i\beta) + \gamma, \qquad \gamma = K_p\,(\theta_{target} - \theta_{robot})
```

α は曲がりの大きさ、ω は波の速さ、β は波の間隔です。距離が20cmを切ったら α = 0 にして止めます。

## Phase A：シミュレーション

Phase A は、2Dシミュの中で蛇がクリックした地点まで這っていき、条件を乱しても8割以上着けるようになれば完了です。今はA1の途中にいます。

- [ ] **A1. 異方性摩擦で前進させる**：FKに縦横で違う摩擦を加える。完了条件は「μ横 > μ縦 で前に進み、μ横 = μ縦 では進まない」ことを確認できること。
- [ ] **A2. γで曲げる**：旋回バイアス γ を変えると、旋回半径がどう変わるかをグラフにする。
- [ ] **A3. クリックした点に行かせる**：閉ループ（γ = Kp × 角度差）を入れ、クリックした点まで到着して止まる。
- [ ] **A4. 実機の制約を入れる**：サーボの可動範囲（例：±60°）と回転速度の上限をシミュに入れても、A3が成り立つ。
- [ ] **A5. 意地悪テスト**：摩擦±50%、関節角の誤差、位置ノイズをランダムに入れても、10回中8回以上到着する（domain randomization）。

各ステップで確かめる問いは次の通りです。

1. 摩擦比 μ横/μ縦 が何倍あれば前進するか
2. 波の速さ ω を変えると速度はどう変わるか
3. 摩擦が途中で変わっても到着できるか

シミュの出力は「関節角のリスト \[φ1, …, φN\]」の形に揃えておきます。こうしておくと、Phase C で出力先をシミュから実機に差し替えるだけで済みます。

## Phase B：実機練習

Phase B は Phase A と並行して進め、4節の実機が机の上で波を流せるようになれば完了です。いきなり全節を組むと、失敗したときに機械・電気・プログラムのどこが原因か分からなくなるため、小さく試してから増やします。

- [ ] **B1. サーボを1個だけ動かす**：マイコン（ESP32など）から角度を指令し、現在角度を読み返せる。
- [ ] **B2. 2〜3関節で波を流す**：関節ごとに位相をずらした sin 波が流れるのを目で確認できる。前進しなくてよい。
- [ ] **B3. 部品と予算を決める**：サーボの型番と個数、マイコン、電源、車輪、ネジ類を決める。サーボ代が大半を占めるので、節の数（8〜12）は予算から決める。
- [ ] **B4. 1節モジュールを1個だけ作る**：Fusion 360 や Onshape で設計して3Dプリントし、サーボ・ブラケット・受動車輪・配線の通り道が収まることを確認する。量産はこの後。
- [ ] **B5. 電源を設計する**：サーボは負荷時に1個あたり数Aを流すことがある。バッテリー容量、ヒューズ、マイコン用の降圧回路を決め、最初は電流制限付きの安定化電源で有線テストする。
- [ ] **B6. 4節で組み、動けば全節に増やす**：4節で前進の気配があれば、8〜12節に増やす。

| 部品 | v1の候補 | 役割 |
| --- | --- | --- |
| サーボ | Feetech STS3215、Dynamixel XL430 など | 関節。角度を読み返せるシリアルバス式 |
| マイコン | ESP32 | サーボへの指令と無線通信 |
| 車輪 | 各節の腹に受動車輪を左右2つ | 前後は転がり、横は滑らない＝異方性摩擦 |
| 電源 | サーボ電圧に合うリポ／最初は安定化電源 | 全サーボの同時駆動を支える |
| カメラ | USBカメラ1台＋ArUcoマーカー | 位置と向きの計測（Phase C） |

## Phase C：合流して v1 完成

Phase C でシミュと実機をつなぎ、実機がマーカーまで這っていけば v1 完成です。A5 と B6 の両方が終わってから始めます。

- [ ] **C1. 開環テスト**：シミュで決めた α, ω, β をそのまま実機に流し、前に進むことを確認する。
- [ ] **C2. シミュと実機の差を測る**：同じパラメータで、進む速さと旋回半径を両方で測って比べる。差が出たら、シミュの摩擦係数を実機に合うように調整する。
- [ ] **C3. 外部カメラで位置を取る**：天井カメラで頭と目標の ArUco マーカーを認識し、蛇の位置と向きを PC 上にリアルタイムで出す。
- [ ] **C4. 閉ループで到着させる**：PC で計算した γ を無線で送り、10回中8回以上マーカーの半径20cm以内に着いて止まる。

C2 が「現実の摩擦をどう扱うか」への答えです。摩擦係数は机上で完璧に求めるのではなく、実機の動きから逆算します。

```
歩容生成器 → 関節角のリスト [φ1, …, φN] → シミュ or 実機
```

上の層（目標方向の計算、γ の決定）は同じコードのまま、出力先だけを切り替えます。

## 進め方のルールと今週やること

今週は A1 を終わらせ、B1 用の部品を注文します。

- [ ] A1：異方性摩擦を入れ、μ横 > μ縦 で前進するか確認する
- [ ] B1 用にサーボ1個とマイコンを注文する

進め方のルールは次の3つです。

1. **各ステップに完了条件を1つ決める**：「リアルな蛇を作る」は終わらないが、「クリックした点に着いたか」は Yes/No で終わる。
2. **依存関係を先読みしすぎない**：「摩擦 → 静止摩擦 → 接触圧 → 変形…」と連想が続いたら、今のステップの完了条件に必要かだけを見る。
3. **Codex には1ステップずつ頼む**：「蛇シミュを作れ」ではなく「A1 の摩擦関数を20行で足して」のように小さく依頼する。使用量もバグの範囲も小さくなる。
